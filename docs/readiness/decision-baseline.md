The current published baseline is v0.3.5 with report schema `0.8`; the [v0.3 contract](../v0.3-contract.md), [limitations](../limitations.md), [application evaluation](../laravel-coverage/application-evaluation.md), [machine-readable run record](../laravel-coverage/application-evaluation.json), and [product/engineering review](../../.claude/audits/2026-10-10-product-engineering-review.md) are the source records. R1 closed F1 in the development branch by clearing inherited `COMPOSER` for every scenario and diagnostic process. The real offline regression first failed on compatible mode: the successful requested `^2.0` solve returned the original `1.0.0` lock, while the impossible `^3.0` request ran against the original manifest and wrote its disposable lock. With the repair, compatible and restricted mode both solve the requested target and keep the original manifest, lock and source bytes unchanged on success and failure; cleanup and explicit debug retention are checked. The repair preserves schema `0.8`, the PHP `^8.0` floor, and the public execution options, so it is patch-compatible. Any private advisory, disclosure timing, or separate v0.3 patch belongs to the maintainer's existing security/release process; this readiness work creates no release tag and sends no external notification.

Missing effort is displayed as not estimated; enforced stage limits and advisory memory/report-size targets are labeled separately, with absent measurement left absent. The [five report-state next-action checklists](report-reading-checklists.md) were independently reviewed as engineering evidence, not tested with users. New structured completeness, measurement and nullability semantics remain Milestone 0 decisions.

Verification is recorded precisely: the full Docker `composer check` passed schema/Wiki validation, 1,396 unit tests (10,090 assertions), 98 integration tests (5,994 assertions) and two smoke tests (five assertions), then stopped at three missing PHPStan iterable-value annotations in new helpers. Final PCOV unit run passed 1,399 tests (10,098 assertions), with 12,263/12,734 executable lines covered; the selective mutation gate killed all 18 configured mutants, and PHP 8.0 focused qualifier and Markdown tests passed. Independent source review approved R2 with no open findings. This composed evidence does not claim that a final full `composer check` completed after the annotation fix. Reader comprehension, planning-time benefit, application runtime safety and actual budget measurements remain unobserved for R3/R4.

## Intended reader, choice and distribution hypotheses

**Provisional first user:** a senior PHP/Laravel lead or upgrade consultant deciding scope, sequence and budget *before* implementing a Composer/PHP/Laravel upgrade. An engineering manager or agency owner may approve that work, but the user and buyer roles have not been verified. The decision job is to identify the first evidenced dependency blocker, a next safe action, source/manual work and what remains unknown. A useful report would combine solver outcomes, carried staged candidates, source references and explicit limits in one local shareable artifact; R3 must test whether that improves decisions enough to justify setup and reading time.

The [review's official-source comparison](../../.claude/audits/2026-10-10-product-engineering-review.md#product-and-business-assessment) is the bounded alternative set: [Composer `prohibits`/`why-not`](https://getcomposer.org/doc/03-cli.md#prohibits-why-not) exposes dependency constraints; [Laravel upgrade guides](https://laravel.com/docs/12.x/upgrade) and manual engineering cover migration work; [Rector](https://getrector.com/documentation) previews or applies refactors; [PHPCompatibility](https://github.com/PHPCompatibility/PHPCompatibility) checks PHP source compatibility; [PHPStan](https://phpstan.org/user-guide/getting-started) checks static errors; [Laravel Shift](https://laravelshift.com/faq) supplies upgrade changes for review. The proposed incremental value is an earlier evidence-linked scope and sequence decision, not replacement of these tools. Whether that advantage exists in practice is untested.

**Discovery/install hypothesis:** reach upgrade owners through the repository/Packagist documentation and relevant PHP/Laravel upgrade discussions, then let them install the published CLI and Laravel adapter in a separate Composer tools directory following [installation guidance](../installation.md). A task study must record how long discovery, installation, execution and reading take; no acquisition or conversion rate is claimed. MIT and a quiet issue tracker supply no evidence of repeat use, buyer demand or revenue. The current direction remains `VALIDATE_FIRST` for Symfony until R3/R4 evidence and R5's recorded decision.
